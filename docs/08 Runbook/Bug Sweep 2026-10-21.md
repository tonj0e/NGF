# Bug sweep 2026-10-21

Five parallel reviews (finance, access control, loan flow, DevOps, pages). Typecheck clean after the fixes. Nothing was run against the live database.

## Fixed
- **Dates**: `lib/dateUtils.ts` helpers (`addDaysIST`, week start/end, due Saturday, display) were one day early. Commission cycle was 34 days instead of 35 (payouts unlocked a day early); collections week started Friday. Dashboard windows and the commission unlock date now move by one day.
- **Payment links**: a payment on a link that had been replaced (Cancelled) was never credited. Now claimable.
- **Repayments**: double-click / two devices could pay one week twice; a week with a UTR payment waiting could be paid by hand. Now one conditional claim plus a payment-line check. Loans with Waived weeks now complete.
- **Amounts**: NaN or negative amounts rejected in deposits, deposit requests, settlements.
- **Leads**: finished leads can no longer be reassigned, rejected or re-verified; unknown loan product no longer disburses as the first product; new leads need a valid guarantor and cannot reuse an Aadhaar with an open lead; only Guarantor/Admin/Staff create leads. OTP: changing the phone allows a new code; renewal "verified" badge matches the 1-hour rule.
- **Access**: Staff of another branch could edit, assign or delete a lead (now branch-checked); a Guarantor with no record saw the whole collection sheet (now empty); the generic settings API could write `integration:*`/`gateway:*` keys (blocked); one-time dev routes (`dev/fix-passwords`, `seed-admin`, `migrate-*`, `drive/auth`, `drive/callback`, `setup`) now return 404 in production. To reconnect Google Drive, run drive/auth on the local dev server.
- **Pages**: agent live location was never sent (stale state); Reports crash on failed fetch, wrong "last month" and "today" (now IST); fake notification bell items removed; notifications shown in IST; spinner-forever on failed loads.
- **Logs**: login route no longer logs username/role/password result.

## Open, owner decision
- Staff are branch-scoped only on leads, loans/close, payment links and renewal OTP. Customers, loans, repayments, deposits, settlements, payouts, Drive files and profile are still visible to every branch's Staff. At least restrict customer DELETE to Admin.
- Agents can override the customer OTP with a 10-character reason; agents can type any phone for the OTP.
- Payout approval is not atomic and does not recheck the amount; migration `20261019120000_payout_one_pending.sql` is still not applied.
- Manual deposit ledger accepts withdrawals above balance; early closure ignores waiting payment lines; duplicate payment on a Paid link raises no alert; Failed-then-paid link not credited.
- CSRF check does not await token verification (not exploitable today, Bearer auth); `CSRF_SECRET` has a hardcoded fallback.
- Migration history out of sync with live; root `migrations/` duplicates `supabase/migrations`; stray `node_modules 2/3` folders.
- Remaining debug logs in loan-products, staff and DevPage.
