## ngrok auto-start
- Memory note of 2026-10-19 said "ngrok tunnel" was done, but no startup entry existed on the Mac (it was started by hand or was lost). Created launch agent `com.ngf.ngrok` (`~/Library/LaunchAgents/com.ngf.ngrok.plist`): waits for the internet and for the local site, then runs `ngrok http 3000`. Log: `~/Library/Logs/ngf-ngrok.log`. Current link is shown at http://localhost:4040.
- The free tunnel gets a NEW random address after every restart. To keep one fixed address: claim the free domain in the ngrok dashboard (Domains) and add `--url=<domain>` to the plist.

## Bug: Edit User did not save permissions (owner video, 2026-10-23)
- Symptom: on NGF Branches > Edit User (e.g. accountant Vincent) ticking more permissions and pressing Update User showed "User updated successfully" but nothing changed.
- Cause: `components/pages/StaffPage.tsx` `handleAddUser` sent branch, branch role and permissions in a PATCH to `/api/staff`, but that route only saves name, username, email, role and password. Permissions live in `staff_access`, branch role in `branch_staff_roles`.
- Fix: after the PATCH, the form now calls `POST /api/branches` `setAccess` (permissions) and, if the branch role changed, `setStaffRole` (old role off, new role on; one-manager-per-branch rule still applies). Same pattern the guarantor edit already used.
