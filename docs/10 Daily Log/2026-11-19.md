# 2026-11-19

## Speed (perf/eng3)
- `companyTotals()` (`lib/db.ts`, database function `company_totals`, whole-table sums) is kept 45 s per server process with one shared in-flight call; used by staff list, projection, financial analytics, capital, Admin assistant, org chart. Figures can be up to 45 s old.
- `GET /api/staff?agents=1`: agent list only (same permission check), used by the Leads assign-agent pop-up instead of the full staff list (no users, guarantors or totals).
- `lib/supabase-db.ts`: the column-name lookup used for every row read is built once instead of per row (same output).
- Browser: the Sentry code is downloaded only when a key exists, 4 s after load (`instrumentation-client.ts`), and the QR reader (`jsqr`) only when the sign-in QR step opens: smaller sign-in page.
- Staff / custom-page guarantors: the first page picked from permissions is remembered on the device, so the app opens it straight away instead of Notifications first and then jumping. Not tested in a browser; `next build` not run (worktree with linked node_modules).
- Leads list API speed (branch perf/eng4): tab badges in one database call (`lead_badge_counts`, migration file only, not applied; falls back to the seven head counts until it is), `counts=0` for the agent's Verifications list, follow-up reads select only the columns used (same-Aadhaar check no longer downloads whole leads), agent row read in parallel with the scope. See [[Lead to Loan]].
- Speed (branch perf/eng5): Customers list enrichment 4 -> 3 waiting database steps (loans passed into `bulkScores`, overdue from the weekly rows already read, leads read with only the shown columns); "no page" lists of customers and loans count once and read the other pages 5 at a time (`lib/pageAll.ts`); Guarantors page loads a light loan list (`/api/loans?filter=all&light=1`) instead of every loan and every customer with full details, and reads one guarantor's full loans and the id/name/phone customer list (`/api/customers?light=1`) only when opened. Numbers checked identical with a read-only old-vs-new script on live data. See [[Scale and Speed]].
- Speed (branch perf/eng6): `/api/oreo/overview` runs everything in one `Promise.all` and keeps answers 30 s per process; new `?card=1` light answer used by the home Saturday card; Oreo sums page past the 1000-row cap (`readAll`). `/api/collection-status` sums cash in the database filter (`payment_mode = 'Cash'`, amount column only) and skips the guarantor list on `lite=1` polls. `/api/dashboard` reads the guarantor's commission cycle in the first `Promise.all` with only the needed columns, inside the 45 s cache. See [[Oreo]], [[Repayments and Collections]], [[Commissions and Payouts]].
